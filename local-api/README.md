# Delphi local API

This standard-library Go 1.23 module provides local, explicit-context structural evaluators for Prototype and Design System artifacts plus Landing/Roadmap knowledge status and human review recording. It is a local CLI contract, not an HTTP service, hosted API, IAM boundary, publication, or approval service.

Run `delphi-ai/local-api/run` from the selected Project Git checkout and provide identities only. The ignored `private-context.json` configures the API-owned shared state root. The API resolves a registered Project's existing binding (and rejects a different checkout); an unregistered Project uses Delphi's sole managed `foundation_documentation` convention. `builder-project list` works from any directory. No caller supplies state, workspace, Project, Foundation, or binding-file paths.

The Prototype, Design System, and Knowledge evaluator commands return fresh JSON and do not persist snapshots. With no configured Design System binding file, the evaluator validates the standard Project source in memory; this is working-tree-only and committed mode still requires an explicit pin. A present but invalid configured map never falls back. `record-review` writes only the selected review marker after checking the exact Foundation, target, full revision, expected packet digest, reviewer label, and reference. Separately, `builder-project list` and `status` are read-only; `register` writes registration metadata and an immutable content snapshot, and `decline` writes a context-bound optional-integration preference. See `contract.md` for each operation's lock, atomicity, and failure semantics.

Optional local Builder integration is provided by `run builder-project list|status|register|decline`; see `contract.md` for exact flags and response semantics. It stores explicit registrations and immutable snapshots in a private local file store, not a database or HTTP service. Registration is never part of ordinary initialization, missing artifacts do not block selection, and decline cannot unregister an existing Project. Fresh artifact checks are independent of registration and support `--artifact-kind`; Prototype checks also require `--artifact-id`.

Use `run test` and `run test --race` for Docker-owned verification. Go and Git are not required on the host. Compilation, tests, and fixture Git operations execute as the invoking UID/GID with private temporary Go caches; the fixture runner creates synthetic repositories under host temporary storage.
